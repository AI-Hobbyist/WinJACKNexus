# 广播系统运行与增量替换

适用 Windows x64、Qt 6.10.3 的现有 WinJACKNexus Release 安装。此交付是增量覆盖包，不是完整安装包；现有应用、公共 UI/audio/common DLL、Qt Core/Gui/Widgets 和 Windows VC++ 运行库继续使用。不要在应用或音频进程正在运行时覆盖占用文件，本次构建没有终止这些进程。

## 客户端

将客户端增量覆盖包解压覆盖到现有应用可执行文件所在目录，保留 ZIP 中相对路径。新增 `nodes/bc/mod_broadcast.dll`、`nodes/bc/locate`、`broadcast_runtime.dll`、Qt Network/WebSockets 及 `tls/qschannelbackend.dll`。不包含测试夹具、测试程序、用户设置、Token 或无关模块。已有自定义 qt.conf 插件路径的安装应将 TLS 插件放入其对应的 `tls` 子目录。

节点仅支持 JACK。添加广播节点后打开独立窗口：左侧可建立多级分类、添加流、编辑名称/父分类/布局及删除项目；非空分类须先移动或删除内容。支持单声道、立体声、5.1、7.1。输入端口接要广播的源，输出端口是每条流独立的同布局本地监听，不自动混音或下混。

顶部填写统一服务器地址，例如 `https://host:9443/bc`、发布者 ID 和发布 Token，点击“保存服务器”，再“开始推流”。所有广播窗口共用这组配置和一个发布会话。保存连接配置会停止当前发布，需要显式重新开始。Token 留空表示保留已存凭据；新 Token 保存成功后从编辑框清空。凭据存于 Windows Credential Manager；服务器地址、发布者 ID、凭据引用存于当前用户的应用全局设置，工程文件不包含 Token。

每轨仅一个总体峰值电平表，取所有声道处理后的最大绝对样本。增益平滑作用一次，M 同时静音广播和本地监听，S 仅影响本节点本地监听；实时监听默认关闭，新建或工程恢复也关闭 Listen/S。关闭窗口只隐藏界面，不停止处理或推流。监听在本地直接处理，不从服务器绕回。

发布失败或断网不停止本地监听。普通连接错误按 1/2/4/8/16/30 秒退避；凭据错误或身份占用终止重试，修改后重新开始。发送队列上限 100ms；过期/源时间轴缺口导致明确发布错误时，检查负载并重新开始发布。显示的 UDP 字节/报文是本机系统接受的发送量，源丢帧和过期帧也属于发送端；控制 RTT 不是音频端到端延迟，也不是服务端收包率。

## 独立服务端

独立服务端定位为远程音频功能的公共后端，目前实现广播发布和转发，后续规划扩展其他涉及远程音频的功能。后续能力尚未实现，不因本说明列出而视为可用；当前可执行文件名仍为bc-server。

将服务端包解压到单独目录。它不需要 WinJACKNexus、Qt、JACK、音频设备或音频编码器。将随包 `server.example.json` 复制为 `server.json`，准备其引用的 UTF-8 Token 文件，启动：

```powershell
& ./bc-server.exe --config ./server.json
```

Linux 使用 `./bc-server --config ./server.json`。JSON 可设置 bind、udp_bind、publish_token_file、tls_cert、tls_key、insecure_loopback；文件路径相对于配置文件目录。命令行覆盖配置，命令行文件路径相对于启动目录。TLS证书和私钥均可不配置（省略或null），此时提供HTTP/WS，可由NGINX反代终止外部TLS；配置两者后才启用HTTPS/WSS，只配置一个会报错。客户端仍连接NGINX公开的HTTPS地址，证书验证保持。

`nginx.example.conf` 提供HTTP/WS反代示例，需改成实际域名及NGINX已有证书路径，关闭流响应缓冲并转发WebSocket Upgrade。UDP 9444不走HTTP反代，仍须独立到达与控制连接同一个公网地址上的relay；NGINX异机时另配UDP转发。

若服务端直接终止TLS，原命令行仍可使用：

```powershell
& ./bc-server.exe --bind 0.0.0.0:9443 --udp-bind 0.0.0.0:9444 --publish-token-file C:/Secure/bc.token --tls-cert C:/Secure/server.pem --tls-key C:/Secure/server-key.pem
```

放行服务器 TCP 9443 和入站 UDP 9444。发布客户端向服务器发起控制和 UDP 连接；听众仅使用 TCP。发布控制需要 Bearer Token，匿名听众没有发布权限，不需要 Token。服务端只注册、鉴权、重组、选择声道、封装和转发，不编码、解码或重采样。不自动安装系统服务。

仅本机开发可使用显式 loopback 明文配置：

```powershell
& ./bc-server.exe --bind 127.0.0.1:9443 --udp-bind 127.0.0.1:9444 --publish-token-file C:/Secure/bc.token --insecure-loopback
```

此时客户端地址填 `http://127.0.0.1:9443/bc`。`--insecure-loopback`仍仅允许回环绑定；供NGINX后端使用的普通无证书HTTP/WS模式不需要此开发标志。TLS启用时证书验证不能跳过。UDP上行有HMAC鉴权及完整性保护，但不由TLS加密。

## HTTP 收听

在窗口中选择一条流、完整流 `all` 或分声道、Opus/WAV，点击复制收听地址。示例：

```text
https://host:9443/bc/listen?publisher=station&stream=流UUID&channel=all&format=opus
```

`publisher` 和 `stream` 必填，`channel` 默认 `all`，`format` 默认 `opus`。`format=wav` 返回源采样率 PCM16，Content-Type 为 `audio/wav`；Opus 为 48kHz Ogg，Content-Type 为 `audio/ogg; codecs=opus`。立体声/环绕声可订阅 `L/R/C/LFE/Ls/Rs/Lrb/Rrb` 中实际存在的原始声道；单声道为 `M`。分类和显示名不进入稳定地址。

浏览器直接打开音频 URL 的产品目标是出现原生播放控件，点击播放，无需自定义网页。浏览器控件及人工播放验收按用户指令跳过，本次没有用 CLI 结果替代浏览器通过结论。

`Broadcast-Listener-20261107.zip` 是独立最小 CLI，无需 Qt/JACK 或发布 Token：

```powershell
& ./bc-listen.exe --list-devices
& ./bc-listen.exe --url 'https://host:9443/bc/listen?publisher=station&stream=流UUID&channel=all&format=opus' --reconnect
```

可用 `--device ID` 选择设备；`--check --frames 48000` 只解码检查，`--pcm-out output.f32` 导出交错 float32le。设备必须支持请求布局和采样率，不自动下混。7.1 设备/WAV 顺序为 L,R,C,LFE,Lrb,Rrb,Ls,Rs；界面/JACK 规范顺序为 L,R,C,LFE,Ls,Rs,Lrb,Rrb，Opus 封装遵循其标准顺序。中途加入 Opus 的解码起始收敛不宜用前 50ms 峰值判断精确增益，精确样本以 WAV 核对。

## 清单、依赖与验证边界

每包 `manifest.json` 记录逐文件 SHA-256，旁边 `.zip.sha256` 记录 ZIP 哈希。打包器验证精确清单、x64 PE、JSON、ZIP CRC 和逐文件哈希。客户端原生 libopus 1.6.1、libsamplerate 0.2.2 静态链接，附 COPYING；Qt 网络库动态链接，附许可证及源码链接。Windows Schannel TLS 插件部署依据 [Qt 官方 TLS 文档](https://doc.qt.io/qt-6/ssl.html)，不额外捆绑 OpenSSL。

已执行离线模型/真实 DLL/真实 UDP 与 HTTP/标准容器解码/Windows 可见实窗程序化验证。S5 的 JACK 边界采用显式加载的仓库离线夹具，实际执行节点 DLL 注册回调，向输入缓冲写信号并观察输出；不会连接真实 JACK 服务。它证明该回调和网络链路，不证明现场 JACK 连线或音频硬件。

真实 JACK/环绕硬件现场验证未执行；浏览器控件、人工界面观察、听音、安装及目标网络验收已跳过（用户指令），均未记 PASS。没有使用 Computer Use、替代外部 UI 自动化或 Qt offscreen。
