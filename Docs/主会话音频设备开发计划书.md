## 1. 目标与用户需求

在全局设置的设备设置区域增加“主会话音频设备”。使用本功能前，必须由用户安装 Virtual Audio Cable、VB-CABLE 或同类受支持的虚拟声卡。用户选择该虚拟声卡的播放端点并将其设置为 Windows 系统默认播放设备后，外部应用使用该设备产生音频会话时，接线盘自动出现对应 exe 的音频来源节点，用户可以将其输出端口连接到现有节点。

| 用户需求 | 计划行为 |
| --- | --- |
| 必须安装虚拟声卡 | Virtual Audio Cable、VB-CABLE 或同类受支持虚拟声卡为启用前提；应用不代为安装驱动 |
| 最低系统版本 | 普通桌面系统最低 Windows 11 21H2（Build 22000）；底层进程捕获 API 最低 Build 20348，普通 Windows 10 22H2（Build 19045）不支持 |
| 全局设备设置增加主会话音频设备 | 增加单选设备字段，默认“未设置”，仅允许选择已识别、受支持的虚拟声卡播放端点 |
| 悬浮提示：实验选项 | 字段标签和选择控件绑定提示，明确实验性质与系统默认设备要求 |
| 想要生效，需要设置为系统默认音频设备 | 将设置值与 Windows 默认播放端点比较；不满足时显示未生效原因 |
| 设置后隐藏 WASAPI In 中相关设备 | 从 WASAPI In 的可选设备列表和自动选择路径中排除能明确关联的对应输入端点 |
| 外部应用使用该设备后自动出现 exe 节点 | 监听选定播放端点的音频会话，自动生成真实可连接的应用音频来源节点 |
| 底层直接使用 exe 完整路径 | 以规范化 exe 完整路径作为持久化应用身份；唯一匹配的应用重新出现后，自动恢复工程中已保存的连接 |
| 与 jackd 采样率不一致时实时重采样 | 以实际捕获 PCM 采样率为源、当前 jackd 采样率为目标自动实时转换；一致时直通 |

悬浮提示中文文案固定为：

> 实验选项。如果想要生效，则需要将其设置为系统默认音频设备。

设备设置区域另显示前提说明：

> 使用前必须安装 Virtual Audio Cable、VB-CABLE 或同类受支持的虚拟声卡；主会话音频设备仅支持选择这些虚拟声卡的播放端点。

## 2. 范围与语义

### 2.1 主会话音频设备

- 主会话音频设备是外部应用提交播放音频的 **Render 播放端点**，不是麦克风等 Capture 录音端点，也不是 JACK 后端设备设置。
- 必须先安装 Virtual Audio Cable、VB-CABLE 或同类受支持的虚拟声卡；仅选择这些已存在设备的播放端点，不允许选择物理扬声器、耳机、HDMI、蓝牙音频设备或普通录音设备。
- 本计划实现虚拟设备识别与选择限制，不开发、安装或创建新的虚拟音频设备驱动。
- 设备列表只包含经验证支持的虚拟声卡播放端点和“未设置”。没有合格设备时，保留“未设置”，禁用有效设备选择并提示先安装受支持虚拟声卡；不得回退到物理默认设备。
- 受支持设备按已验证的驱动/设备身份规则识别，结合驱动提供商、硬件或设备实例标识、端点属性等证据。仅将产品名写成字符串匹配条件不构成可靠识别；不允许改名后的物理设备混入列表。
- S1 确定 Virtual Audio Cable、VB-CABLE 的识别规则及支持清单；其他同类设备只有在身份识别和端点关系验证通过后才可纳入。无法可靠识别的设备默认不可选，不增加用户绕过限制的入口。
- 选择限制同时覆盖 UI 下拉列表、配置加载和运行时服务启动；手工修改配置不能绕过。旧配置指向非受支持设备时保留原值用于说明原因，但不将其作为有效选择，也不启动捕获或隐藏无关设备。
- 使用稳定的 Windows endpoint ID 保存选择，不用设备名称或枚举序号充当身份。
- 设置为应用级全局配置；工程保存不覆盖该设置。
- 当前代码的 `GlobalSettingsDialog` 已有应用设置等区域，实施时在该窗口补充设备设置分组，仅加入本功能必要字段，不重做整个设置窗口。
- “系统默认”首先核对现有设备枚举使用的 `eRender/eConsole` 默认端点；多默认角色差异在 S1 记录。不得将默认通信设备误判为已经满足普通播放要求。
- 本功能不自动修改 Windows 默认设备；由用户在系统中设置。应用仅检测状态并提供提示。

### 2.2 生效与设备隐藏

- 选择保存后，立即更新 WASAPI In 的相关设备过滤；取消选择或切换设备后恢复旧设备的可选性。
- 自动会话节点功能仅在受支持虚拟声卡已安装、所选端点身份校验通过且存在、系统支持捕获、所选端点满足默认设备要求时进入就绪状态。
- 未满足条件时保留选择，显示具体状态，不自动改选其他设备或生成假的可连接节点。
- Capture 与 Render 的 endpoint ID 不相同。对应关系必须来自可核实的设备拓扑、容器信息及端点属性；不允许仅凭名称相似就隐藏设备。容器相同也不能单独证明两端点构成音频回送对。
- 针对虚拟声卡，S1 必须核实每条虚拟线缆播放端点与其对应 Capture 端点的映射；隐藏仅作用于所选线缆的对应输入端点，不隐藏同一驱动下的其他线缆。无法确认映射的设备暂不列入支持清单，不通过名称猜测或扩大隐藏范围。
- 隐藏仅约束新选择和默认自动选择。已经运行或从工程恢复的 WASAPI In 不自动删除、不替换设备、不强制停止；保留当前选择显示并标明已由主会话功能管理，防止静默改变旧工程。

### 2.3 应用节点

- 节点显示名称使用实际音频会话对应进程的 exe 文件名，例如 `chrome.exe`，不按程序窗口标题猜测音频来源。
- 一个运行进程在主端点有多个会话时，只创建一个对应运行实例节点，避免同一音频被重复捕获。
- 同名 exe 的不同进程实例使用 PID 等运行标识区分；运行身份至少包含主端点 ID、PID、进程创建时间，防止 PID 复用导致错误绑定。
- 底层持久化应用身份直接使用实际音频进程的 **exe 完整路径**；显示层仍使用 exe 文件名。路径从真实进程查询，规范化为绝对路径并统一分隔符；按 Windows 路径语义比较，避免同一路径因表示差异产生重复身份。不按文件名、窗口标题或 PID 进行跨启动匹配。
- 默认只捕获该运行实例的范围。若底层只能按进程树捕获，必须在 S1 证明所选范围不会与其他节点重叠；不能同时创建父进程树节点和包含同一音频的子进程节点。
- 输出端口是可连接的真实音频端口，使用现有通道命名和接线盘机制。首次出现且工程无已保存连接的应用不自动连线；存在已保存连接时按第 2.4 节恢复，不新增工程未记录的路由。
- 暂停播放和会话短暂 inactive 不立即销毁节点；会话重新 active 时复用节点。全部相关会话 expired、进程退出或离开主端点后释放捕获资源并移除动态节点。
- 排除 WinJACKNexus 自身及其已知音频工作进程，避免将自身输出重新捕获造成反馈。
- 运行 PID 不持久化为跨启动身份。工程保存 exe 完整路径、节点布局、标准输出端口标识和连接目标；无法唯一匹配时保留待匹配状态，不猜测连接到另一个同名 exe。

### 2.4 存档与按完整路径恢复连接

- 工程加载时读取已保存的应用身份与连接意图；应用尚未运行或尚未创建主设备音频会话时，保留待匹配记录，不主动启动外部 exe。
- 外部应用在主设备创建会话后，获取实际音频进程的 exe 完整路径。只有路径匹配且可用运行实例唯一、捕获初始化和输出端口发布成功，才自动恢复已保存连接。
- 恢复同时要求目标节点与目标端口存在；尚不可用时保留连接意图，待必要节点/端口出现后重新匹配。重复会话通知或重复匹配不得重复创建连接。
- 同名但路径不同的 exe 不匹配；程序迁移路径后保持待匹配。查询进程路径失败时，不用文件名回退，不执行自动恢复。
- 同一完整路径同时存在多个可捕获实例时，路径不足以唯一标识运行实例。不得随机选择、按 PID 大小或启动顺序猜测；保留待匹配状态及原因，待候选唯一后再恢复。首次发现多个实例时仍按第 2.3 节分别呈现运行节点。
- 若工程保存了同一路径的多个实例节点，仅凭路径不能还原各实例的连接归属；这些记录保持待匹配，不将所有连线合并到一个实例。实例级持久化匹配策略不在本次范围内。
- 进程退出、会话失效或暂时关闭本功能时，释放运行资源但保留已保存的应用节点描述和连接意图。用户主动删除节点或连线后更新记录，不在后续通知中恢复用户已删除的连接。
- 只恢复当前工程中的主会话应用来源连接，不扩展为其他节点的通用自动重连服务。

## 3. 技术基础与首要限制

### 3.1 会话发现和进程音频捕获是两条链路

会话发现限定在所选设备：

```text
主播放端点 IMMDevice
  → IAudioSessionManager2
  → 初始会话枚举 + IAudioSessionNotification
  → IAudioSessionControl2 / 会话状态事件
  → PID 与 exe 元数据
```

音频捕获使用 Windows Process Loopback：

```text
目标 PID / 经验证的进程范围
  → AUDIOCLIENT_ACTIVATION_PARAMS
  → ActivateAudioInterfaceAsync(VIRTUAL_AUDIO_DEVICE_PROCESS_LOOPBACK)
  → IAudioClient / IAudioCaptureClient
  → PCM 缓冲与现有重采样链路
  → 应用节点输出端口
```

会话管理接口不能直接读取某会话的 PCM。普通 endpoint Loopback 得到设备上的混音，也不能分离成各 exe 的音频。

### 3.2 端点筛选不能替代端点级音频隔离

微软官方 Process Loopback 按目标进程及其子进程筛选，并不绑定具体播放端点。因此“在主设备上发现了某进程”不代表捕获数据仅来自该进程送往主设备的流。

S1 必须验证同一应用同时向主设备和其他设备播放的场景，并记录实际捕获范围。若公开接口无法满足按主设备隔离音频的要求，不能将跨设备的进程混音直接冒充主设备会话音频交付。届时说明受影响模块、可用范围及是否需要改变捕获语义或引入其他技术，等待用户对必要范围调整的明确批准。

同理，跨进程会话的 `GetProcessId()` 可能返回 `AUDCLNT_S_NO_SINGLE_PROCESS`；不能把返回的最初创建者 PID 当作全部音频来源。S1 验证可归属的普通进程会话；无法确定来源的会话保持不生成可连接节点，并记录原因。

### 3.3 支持条件与音频路径

#### 3.3.1 最低系统版本要求

本要求仅针对“主会话音频设备 / 自动 exe 音频来源节点”功能，不改变整个 WinJACKNexus 或现有 WASAPI In/Out 的系统兼容范围。

| 系统范围 | 最低版本或判断 | 本功能的处理 |
| --- | --- | --- |
| 普通 Windows 桌面发行版 | **Windows 11 21H2，OS Build 22000** | 满足底层 API 版本门槛；仍需受支持虚拟声卡和实际捕获激活成功 |
| Windows Process Loopback API | 微软文档标明 **Windows 10 Build 20348** | 这是底层构建号门槛，不表示普通 Windows 10 发行版具备此能力 |
| 普通 Windows 10 22H2 | OS Build 19045，低于 20348 | 不支持本功能；安装虚拟声卡或升级同一 19045 分支的累积补丁不能满足构建号门槛 |
| Windows 10 LTSC 2021 及更早常规版本 | LTSC 2021 为 Build 19044；更早版本低于门槛 | 不支持本功能 |
| Windows Server 2022 | OS Build 20348，满足 API 构建号门槛 | 仅记录技术候选；音频服务、驱动与捕获能力未经本计划验证前，不宣称产品支持 |

版本对应依据：[微软进程捕获激活参数文档](https://learn.microsoft.com/en-us/windows/win32/api/audioclientactivationparams/ns-audioclientactivationparams-audioclient_activation_params)、[Windows 11 发行信息](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information)、[Windows 10 发行信息](https://learn.microsoft.com/en-us/windows/release-health/release-information)、[Windows Server 发行信息](https://learn.microsoft.com/en-us/windows/release-health/windows-server-release-info)。上述最低版本是功能/API 门槛，不等同于微软当前仍提供维护支持的最低版本，也不等同于本项目已完成实机验证。

- 运行时读取真实 OS 构建号，并检查 Process Loopback 异步激活结果；不能仅根据系统营销名称、应用兼容模式中的版本字符串或编译所用 SDK 推断支持。
- 低于门槛时禁用本功能的有效设备选择及捕获启动，并显示：“此实验功能需要 Windows 11 21H2（Build 22000）或更高版本；当前系统不支持进程音频捕获。”同时展示实际系统构建号。
- 保存配置不绕过系统版本检查；其他现有音频节点继续按原行为工作，不退回全设备混音伪装成应用捕获。
- 满足版本要求但激活失败时按 API 错误记录原因，不把版本检查通过当作捕获验证通过。

#### 3.3.2 音频路径条件

- 初始验证限定 WASAPI 共享模式播放；不承诺 ASIO、独占模式或受保护内容捕获。
- 根据真实捕获格式建立端口和转换链路，不默认认为所有应用均为立体声，也不将现有 Native Fx 八通道规定套到应用来源上。
- 复用现有环形缓冲、通道处理和重采样能力。采集工作线程与 JACK 实时回调隔离；实时回调不执行 COM、磁盘读取、进程查询、动态内存分配或阻塞等待。
- 捕获是音频复制。主设备必须为受支持的虚拟声卡播放端点，物理输出通过用户连接的现有音频路径处理。若系统“侦听此设备”或其他软件另行监听该虚拟声卡，仍可能出现重复监听；本功能不自动修改这些外部监听设置，不通过静音目标会话假定仍可无影响取得原始音频。
- 使用虚拟声卡不会改变 Process Loopback 不绑定端点的限制；第 3.2 节的跨端点捕获验证仍必须执行。

#### 3.3.3 强制自动实时重采样

- 每个应用来源节点使用捕获流实际协商得到的 PCM 采样率作为源采样率，使用当前 JACK 客户端查询的 jackd 采样率作为目标；不以应用原文件采样率或虚拟设备面板配置代替实际捕获格式。
- 两者不一致时必须实时重采样后输出到 JACK，不要求用户手工统一采样率。例如捕获 44.1 kHz、jackd 48 kHz 时执行 44.1 → 48 kHz；捕获 48 kHz、jackd 44.1 kHz 时执行 48 → 44.1 kHz。
- 两者一致时采用直通路径，跳过不必要的采样率转换；直通仍遵守现有缓冲和通道转换规则。
- 优先复用现有流式重采样实现。各节点独立保存重采样状态，跨捕获数据包保留相位、剩余输入及滤波历史，不逐包重置；保持音高、播放时长和声道对应关系，不用丢帧、重复帧或修改采样率标签冒充重采样。
- 捕获与 JACK 的数据块长度不要求相等，转换后的 PCM 通过现有有界音频环形缓冲供给 JACK。JACK 回调每次输出规定帧数，欠载时安全补零，溢出按明确的有界策略处理并记录，不能越界或阻塞。
- jackd 采样率回调只发布变化请求；在非实时工作线程更新重采样状态及必要缓冲，并安全切换。捕获格式重建时同样重新核对源采样率；清除旧格式残留，切换期间安全补零，不混用新旧采样率数据。
- 初始化内存、调整缓冲及重建转换器均在非实时线程完成。采样率变化不得通过重启 jackd、终止用户音频进程或中断无关节点处理。
- 本要求覆盖名义采样率不一致及采样率变化；独立设备时钟长期漂移的自适应校正不自动扩大为本阶段要求，若验证证明其为正常运行所必需，则按范围控制规则报告证据。

## 5. 状态与生命周期

| 状态 | UI 与服务行为 |
| --- | --- |
| 未设置 | 功能关闭；WASAPI In 使用原设备列表 |
| 未安装或未检测到受支持虚拟声卡 | 提示先安装 Virtual Audio Cable、VB-CABLE 或同类受支持虚拟声卡；无有效设备可选，不回退到物理设备 |
| 配置指向非受支持设备 | 显示设备类型不受支持；拒绝启用，不隐藏无关设备，不自动改选 |
| 已设置但设备不可用 | 保留配置，显示设备不可用；不枚举替代设备 |
| 已设置但不是系统默认播放设备 | 显示需要设为系统默认；设备过滤生效，自动应用捕获未就绪 |
| 系统不支持 | 显示版本或 API 不支持；不创建捕获节点 |
| 已就绪、无外部会话 | 监听选定端点，接线盘不生成空应用节点 |
| 发现可归属的外部会话 | 去重后建立捕获；成功后发布可连接节点 |
| 捕获失败 | 显示或记录失败，不把无有效捕获的节点标为就绪，不无限重试 |
| 会话暂时 inactive | 保留节点和连接，输出静音，不频繁增删 |
| 会话全部失效或进程退出 | 停止捕获，释放运行端口和动态节点；保留工程中的应用身份与连接意图，等待同路径应用再次出现 |
| 存档应用唯一匹配且端口就绪 | 自动恢复已保存连接；目标端口尚不可用时保留待恢复状态 |
| 同路径多个实例或路径无法查询 | 不自动绑定，保留待匹配状态及原因 |
| 切换或取消主设备 | 更新过滤、撤销旧会话监听和本功能节点；不关闭其他节点、应用或 JACK |

设备热插拔、系统默认设备切换、主设备选择变化通过已有事件通路更新。UI 刷新和动画跟随应用 30/60/120 FPS；不添加固定刷新率的项目视图。系统事件处理不得放到 JACK 实时回调中。

## 6. 分阶段实施与通过条件

必须按 S1 → S2 → S3 → S4 顺序实施。每阶段只完成表中范围，达到预定通过条件后结束，不追加相邻功能。

### S1：可行性验证与最小接入设计

- 确认全局设备设置接入点、现有 WASAPI In 枚举方向，以及受支持虚拟声卡播放端点和对应 Capture 端点的可核实关系。
- 确定 Virtual Audio Cable、VB-CABLE 和其他拟支持虚拟声卡的身份识别清单；覆盖设备改名、物理设备伪装名称、同驱动多条线缆、未安装及驱动卸载情形。实际可用产品分别记录验证结果，不把未验证设备标为支持。
- 用无需 JACK 的工具或测试验证主端点会话枚举、exe 归属和 Process Loopback 数据读取。
- 必测两个独立应用、同一应用跨两个输出设备、同名多进程、父子进程捕获重叠、会话 inactive/expired。
- 记录系统版本、默认设备角色、可支持会话类型、捕获范围、格式及失败条件。
- 若无法保证需求所需的音频隔离或进程归属，报告证据并停止后续实施，不以全设备混音替代。

**通过条件**：虚拟声卡识别和端点关联规则明确，物理设备不能进入有效选择；进程捕获可用；设备范围和节点归属与本计划一致，或必要语义调整已经获得用户明确批准。

### S2：全局设置与 WASAPI In 过滤

- 增加仅列出受支持虚拟设备的主设备字段，复用公共 UI 控件，绑定指定 tooltip、安装前提说明及语言资源。
- 持久化 endpoint ID，处理未安装、未设置、类型不合格、不可用、非默认和不支持状态；配置恢复和服务启动同样执行类型校验。
- 实现已确认的对应设备过滤，并覆盖新选择、自动选择、取消和设备切换。
- 保留已有 WASAPI In 实例和旧工程的当前设备及连接。

**通过条件**：仅受支持虚拟声卡可选，配置不能绕过类型限制；未安装时提示正确；设置可保存恢复；tooltip 正确；对应设备在新选择中隐藏、取消后恢复；无关设备和既有运行实例不受影响。

### S3：会话服务与真实应用来源节点

- 在主端点注册会话通知并建立初始列表，处理通知与初始枚举的竞态。
- 按 S1 确定的运行身份和捕获范围去重；完成 exe 完整路径查询及规范化、捕获启动与停止。
- 接入现有节点和端口生命周期；复用缓冲、重采样与标准通道名称，强制实现实际捕获采样率到当前 jackd 采样率的自动实时转换、同率直通及采样率变化安全切换。
- 覆盖 inactive 复用、expired/进程退出清理、设备切换、捕获失败和自捕获排除。
- 接入工程保存和加载，按完整路径唯一匹配应用，待来源和目标端口就绪后自动恢复已保存连接；覆盖多实例歧义及用户主动删除连接。

**通过条件**：外部应用使用主设备后出现对应 exe 的真实可连接来源节点；不同应用数据隔离；重复通知不重复建节点；退出正确清理。JACK 端口注册及图连接逻辑以离线替身验证，不要求启动 JACK 集成测试。

重采样通过条件：异率输出的帧数比例、测试音频频率、时长与通道对应正确；跨包状态连续，同率直通正确；模拟 jackd 采样率变化后安全切换，无越界、阻塞或旧格式数据混入。以离线音频数据和 JACK 回调替身验证，不要求启动 JACK 服务。

### S4：兼容验证与交付记录

- 验证设置持久化、设备过滤、动态节点和旧工程兼容；验证完整路径存档、应用重启后的连接恢复，以及 PID 复用、同名异路径和同路径多实例不会误连。
- 执行必要 Release 目标的构建、离线测试和真实 Windows 窗口自动验证。
- 更新本计划进度，记录通过项、失败项、人工跳过项及不支持范围。
- 如交付覆盖包，仅包含本次变更必需的运行文件，不标为完整包。

**通过条件**：本计划适用的自动验证通过；限制和人工跳过影响已记录；交付文件与本次构建一致。

### 每阶段检查点
