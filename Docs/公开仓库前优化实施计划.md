# 公开仓库前优化实施计划

日期：2026-10-11。状态：S1～S5 已完成并验证；S6 待实施。

本计划仅覆盖 SF2 加载器按需加载、Node SDK 的 JACK_NODE 与 VIRT_NODE 能力、主图和子图的加载隔离，以及现有节点迁移。当前交付仅为计划书；不包含代码实现，也不更改仓库可见性。后续实施必须按阶段顺序完成，每阶段通过规定的自动验证后更新记录、提交并推送，再进入下一阶段。

## 一 目标和范围

1. SF2 加载器导入文件只登记资源，只有选中资源才加载；切换后释放之前的资源，不让未选中音色库长期占用内存。
2. Node SDK 增加两项可组合的 metadata 能力：JACK_NODE 表示支持主图实例并注册 JACK 客户端；VIRT_NODE 表示支持子图实例，仅执行内部 DSP，不注册 JACK 客户端。一个模块可声明其中一项或两项。
3. 主图仅走 JACK_NODE DSP 路径，子图仅走 VIRT_NODE DSP 路径。主图根据 JACK_NODE 标志显示或隐藏节点，子图根据 VIRT_NODE 标志显示或隐藏节点；库列表过滤、创建、拖放、复制和工程恢复都执行相同限制。
4. 双能力模块按放置上下文创建一种实例，不能因支持 JACK_NODE 就在 VIRT 实例中启动 JACK。
5. 每个直接放在主图中的最外层子图拥有自己的 JACK 客户端；其中全部后代节点走 VIRT 通路。嵌套子图不额外注册客户端或内部 JACK 端口。

不包含通用架构重写、其他性能优化、DSP 音色算法改变、主题重设计、JACK 连接集成测试和完整发布包。发现无关问题只记录后续事项。实现当前目标若确需扩大范围，说明原因、文件、影响及不实施的后果，等待明确批准。

## 三 节点能力清单

能力是模块的支持范围；实例模式由宿主根据所属图选择，不能由工程 JSON 任意提升权限。

| 节点类别 | JACK_NODE | VIRT_NODE | 要求 |
| --- | --- | --- | --- |
| VST Host 节点 | 是 | 是 | 主图用 JACK；子图由宿主提供内部音频及 MIDI 缓冲 |
| 配套 VSTs 插件节点 | 是 | 是 | 包含扫描生成或发现的 VST2、VST3 插件条目，不能只修改 Host 外壳 |
| Native Fx 节点 | 是 | 是 | 所有提供 Node placement 的现有效果模块逐个迁移 |
| MIDI Split | 是 | 是 | 现有源码目录为 `midi_spilit`，本次不顺带改名 |
| MIDI Matrix | 是 | 是 | 保留路由、过滤和参数语义 |
| 子图 | 是 | 是 | 主图实例拥有 JACK 边界；嵌套实例只执行内部图 |
| 子图 Audio In | 否 | 是 | 图外输入映射为图内音频输出 |
| 子图 Audio Out | 否 | 是 | 图内音频输入映射为图外输出 |
| 子图 MIDI In | 否 | 是 | 图外 MIDI 输入映射为图内 MIDI 输出 |
| 子图 MIDI Out | 否 | 是 | 图内 MIDI 输入映射为图外输出 |
| SF2 加载器 | 是 | 否 | 本次只改资源生命周期，不增加子图能力 |
| 其他未指定节点 | 是 | 否 | 包括现有音频及系统 MIDI 适配器、电平表节点、调音台等；以实际清单逐项核对 |

子图和接口节点即使保留宿主内建形式，也必须使用同一能力判定规则，不要求为此拆成新 DLL。外部 JACK 客户端不是 SDK 模块，不伪造 metadata；保留主图既有展示，不能作为子图 VIRT 节点导入。

## 四 SDK 和实例执行契约

### 能力查询与版本

采用显式位掩码表达 JACK_NODE、VIRT_NODE 及二者组合，禁止零能力和未知位。新增创建前可查询的版本化导出，读取 metadata 不创建实例、不调用 init、不连接 JACK。具体 C 导出名称、结构大小和字段类型在 S2 写入 Node API 文档并用 C/C++ 调用点测试冻结。

本计划采用 Node v4 作为目标契约：保留一 DLL 一节点类型，不直接扩展旧 NodeInfo 或 INode 布局并仍自称 v3。提供显式实例模式的创建或初始化入口，宿主必须在任何可能产生 JACK 副作用的初始化前确定模式。模式在实例存活期间固定，跨图移动通过保存状态、销毁旧实例、按目标上下文重新创建完成。

旧 v3、缺失能力导出、非法能力以及能力与处理接口不一致的模块均给出明确诊断并拒绝实例化；不默认补成 JACK_NODE 或 VIRT_NODE。保留原工程记录，不静默删除。内置模块、SDK 示例及测试夹具必须一并迁移；第三方模块需按 v4 重编。S2 完成切换所需声明和适配后再启用严格拒绝，不交付只能读取半套内置模块的版本。

### 图上下文与 DSP 路径及节点可见性

两个能力标志同时约束节点展示和实际 DSP 调度，不只是列表分类。节点库、搜索结果及添加菜单都按当前图上下文过滤；切换主图与子图时重新应用相同规则。

| 模块标志 | 主图显示和执行 | 子图显示和执行 |
| --- | --- | --- |
| 仅 JACK_NODE | 显示，仅使用 JACK_NODE DSP 路径 | 隐藏，禁止创建和执行 |
| 仅 VIRT_NODE | 隐藏，禁止创建和执行 | 显示，仅使用 VIRT_NODE DSP 路径 |
| JACK_NODE 与 VIRT_NODE | 显示，仅使用 JACK_NODE DSP 路径 | 显示，仅使用 VIRT_NODE DSP 路径 |

不允许主图实例回退到 VIRT_NODE 路径，也不允许子图实例回退到 JACK_NODE 路径。双能力模块可共享底层 DSP 算法，但实例的处理入口、缓冲来源和调度必须属于当前图指定的路径，不能同时启动两条路径。隐藏节点仍须在底层创建及执行入口拒绝，不能通过工程恢复或直接调用绕过。旧工程中不符合当前图能力的记录只作不可加载诊断保留，不作为可执行节点显示或调度。

最外层子图作为主图中的节点，其外部实例使用 JACK_NODE DSP 路径；该实例跨越图边界驱动的子图内容全部使用 VIRT_NODE DSP 路径。嵌套子图作为子图中的节点也仅使用 VIRT_NODE 路径。外部 JACK 边界不使任何内部节点获得 JACK 执行资格。

### VIRT 处理接口

VIRT_NODE 必须具有真实内部处理能力，不能仅添加标签。定义或复用满足以下要求的版本化接口：

- 逻辑端口描述包含稳定 ID、方向、音频或 MIDI 类型及通道信息；不以 JACK 端口句柄表示内部身份。
- prepare 接收采样率、最大块长与宿主上下文；process 接收当前帧数、音频缓冲和带块内时间偏移的 MIDI 事件；stop/reset 与销毁责任明确。
- 所有借用缓冲只在当前 process 调用内有效；事件输出容量有限，溢出策略和统计明确；无输入音频输出静音，无 MIDI 输入输出空事件集。
- 内部执行继承根实例的采样率、块长和时间基准。process 不执行文件加载、DLL 加载、内存回收、阻塞等待或 JACK 客户端及端口注册。
- 图编辑在控制侧准备新执行状态，在块边界安全替换；旧状态待回调不再引用后回收。定义多输入混合、MIDI 合并次序和非法环路处理，复用现有语义；无既有反馈契约时明确拒绝零延迟环路，不引入新反馈功能。
- 处理实例、编辑器及模块租约按既有生命周期释放；关闭编辑窗口不能停止图的处理。双能力实例之间参数和 DSP 状态相互独立。

JACK_NODE 通过其 JACK 适配层驱动同一处理核心。子图 VIRT 路径不使用“无 JACK 时假装 init 成功”的方式绕过旧初始化。

## 五 SF2 资源生命周期

本计划将“选中”定义为加载器中明确激活一个资源条目，不是选中画布节点或打开编辑器。资源目录可保存多个文件，但每个加载器实例稳定状态最多驻留一个选中资源；MIDI Bank/Program 仅在该资源内选预置，不再回退加载其他未选中资源。

1. 导入只保存稳定资源 ID、路径及必要轻量信息，状态为未加载；不调用完整音色库准备，也不因默认选中第一项而自动加载。不得为读取预置列表长期保留完整引擎。
2. 明确选择 A 后，由现有工作线程准备 A。加载和卸载不放入音频回调或 GUI 阻塞路径。重复选择已生效的 A 不重载。
3. A 切换到 B 时停止 A 发声，在块边界解除 A 的音符及 generation 引用，工作线程回收 A 后加载 B。采用先释放后加载的单资源策略，切换允许短暂静音；不承诺旧音尾保持或无缝切换，不缓存所有旧库。
4. B 加载失败时保留目录项和失败原因，保持静音，允许重试；不偷偷重新加载 A。空选择、删除当前项及销毁实例都释放驻留资源。删除未选中项不影响当前声音。
5. A→B→C 快速切换只让最新请求生效，过期候选必须回收，不能覆盖最新状态。退出、取消、采样率变化和没有后续音频回调时仍能结束工作线程并回收资源。
6. 工程保存目录和选中 ID，不保存引擎句柄；恢复仅加载已保存的有效选中项。旧工程 preferred 为空时保持未选中，不以资源顺序代选；路径丢失时保留记录并显示错误。
7. 保留现有资源预算，按选中资源判断。用活跃资源数、销毁计数和 preparedBytes 验证释放；进程工作集仅作辅助观察，不以分配器是否立即归还系统页作为唯一通过标准。

加载器现有 SFZ 支持不得损坏。共用目录选择流程时 SFZ 遵循同样的单选生命周期，SF2/SFZ 解码与合成算法不在本次修改范围。

## 六 子图端口和嵌套行为

路径示例：主图 JACK 输入 → 最外层子图 Audio In → 内部 VIRT 节点 → 嵌套子图 Audio In → 嵌套 DSP → 嵌套 Audio Out → 外层 Audio Out → 主图 JACK 输出。MIDI 使用同样的分层映射并保留事件偏移。

- 最外层子图的 Audio In/Out、MIDI In/Out 节点本身仍是 VIRT_NODE；由所属外层子图的 JACK 实例统一注册对应的外部可连接端口。
- 嵌套接口仅形成该子图在父图中的逻辑端口，不自动将全部深层端口平铺为根 JACK 端口。需要对外暴露的路径，通过父层接口逐层连接到根接口。
- 一个根子图及其任意深度后代总共只有该根的一个 JACK 客户端。主图放置两个根子图时分别拥有两个客户端。
- 图、节点、接口和连线使用稳定 ID；显示重命名不能让嵌套端口串线。删除根节点释放其整个实例树，删除嵌套节点仅回收对应子树。
- 添加、删除、重命名接口及恢复工程时，同步父图逻辑端口与根边界映射；失败回滚，不保留半注册或悬空映射。不要让“是否打开子图标签页”决定 DSP 是否运行。
- 旧工程按所属图推导实例模式；子图中的 JACK-only 节点作为不可加载项保留并报告，不自动搬到主图，也不丢弃其参数和连线记录。新格式保存版本和稳定身份，加载完成后由用户保存，禁止静默覆写源工程。

## 八 验证和提交规则

本次仅新增计划书，不运行编译、GUI 或音频测试；执行文档内容检查、差异检查及提交推送即可。以下规则适用于后续实施。

- 只使用现有 `build`，Release 配置；不新建构建目录，不用 `ALL_BUILD`，除非用户明确要求全量构建。VST 阶段保持 `WJN_ENABLE_VST2=ON` 并覆盖 VST2/VST3。
- 每阶段完成既定修改后运行一次所需构建与测试；失败依据 build.log 和已有同时间戳日志、dmp 定位，修复后只重跑必要验证。
- 每条编译、打包或测试命令必须在前台 PowerShell 执行，标准输出及错误通过 `2>&1 | Tee-Object -FilePath "build.log"`，立即保存并检查 `$LASTEXITCODE`；非零先读取日志再继续。覆盖 build.log 前，将阶段证据保存到既有文档目录。
- GUI 使用 `QT_QPA_PLATFORM=windows`、系统字体和真实可见窗口。流程为构建、启动、等待稳定、操作、截图检查、记录、关闭测试窗口；核对 CJK 没有方框。每批所有窗口、菜单、对话框及 tooltip 累计不超过 100 次。禁止 offscreen 及任何等价替代验证。
- GUI 无法运行先诊断部署、平台、字体和环境；仍无法运行写 `MANUAL/PENDING`，不得报通过。人工审校、人工界面、硬件和安装验收默认写“已跳过（用户指令）”，记录范围及未验证影响，不阻塞检查点。真实 JACK 连接和听音结果不在离线通过结论内。
- 不终止运行中的 WinJACKNexus 和音频进程。输出文件被占用时记录具体路径和阻塞状态，不以停止用户进程绕过。
- 新增或修改 UI 复用公共控件与 Theme Token；刷新遵循应用 30/60/120 FPS。若确需新控件，按仓库规则确认归属；本计划不授权顺带改视觉。
- 每阶段完成后依次：更新本计划进度与证据 → 检查 `git status` 和 `git diff` → 格式及 `git diff --check` → 仅暂存本阶段文件 → 检查暂存差异 → 提交 → 推送当前分支 → 确认远端提交一致。推送失败先解决检查点，不开始下一阶段；不得夹带他人修改。

PowerShell 构建模板如下，目标名由各阶段实际 CMake 确认，测试及打包命令使用同一日志和退出码模式：

```powershell
$cmakePath = 'D:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
$stageTargets = @('mod_sf2_loader', 'midi_tools_synth_tests')
& $cmakePath --build build --config Release --target $stageTargets 2>&1 |
    Tee-Object -FilePath 'build.log'
$buildExitCode = $LASTEXITCODE
if ($buildExitCode -ne 0) {
    Get-Content -LiteralPath 'build.log'
    exit $buildExitCode
}
```
