# WinJACKNexus 广播推流系统实施计划书

日期：2026-11-03（Asia/Seoul）

状态：已授权实施 S0—S5。S0/S1/S2已提交推送；S3 JACK-only节点、音频队列、共享发布线程及编码/UDP已实现，Release与5项C++测试（71断言）及39项Python测试通过，正在完成提交推送检查点。S4独立GUI、S5限定联调及增量包未开始。真实JACK与硬件未验证；浏览器及人工验收按用户指令跳过。最新证据见 Docs/Broadcast/Progress.md。

## 1. 目标与边界

**执行修订（2026-11-04，用户指令）：不使用 Computer Use。浏览器原生控件、点击播放及人工界面观察归入人工验收，记录“已跳过（用户指令）”，不计为 PASS，不阻塞 S2/S5 检查点。下文浏览器展示/播放要求仍是产品目标，不代表已经实测；继续执行自动 HTTP 音频头、标准容器/解码、声道/时间轴和音频测试。禁止通过其他 UI 自动化工具绕过本次跳过指令。Qt 程序化自动测试如需运行仍使用 Windows 可见实窗，禁止 offscreen。**

建设由 WinJACKNexus 广播发送节点、独立 Rust 转发服务和最小订阅播放工具组成的 C/S 广播系统。

用户已明确的要求：

- 广播节点**仅支持 JACK**，不实现 VIRT，不进入子图，不创建虚拟处理表。
- 节点可以添加多个独立流，支持自定义名称、分类及多级子分类。
- 一条流可为 Mono、Stereo、5.1 或 7.1；一条流不等于一个声道。
- 输入端口接收要对外广播的源；输出端口提供本地实时监听。
- 每轨有一个总体电平表、M/S、音量旋钮及实时监听开关；监听开关默认关闭。
- 有独立顶层 GUI，优先复用公共控件库与 Theme Token。
- 广播相关节点部署在节点目录的 `/bc` 子路径。
- 使用统一的全局服务器连接路径，避免每轨分别配置服务器。
- 发布连接需要 Bearer Token，普通收听不需要 Token。
- 完整流和分声道均有可选择的路径；立体声、环绕声支持分声道订阅。
- 服务端使用 Rust，独立于 WinJACKNexus、Qt 和 JACK，只做必要的注册及转发。
- **传输方向明确区分：发布端 → 服务端的音频使用 UDP；服务端 → 听众使用 HTTP 实时响应，通过 GET 参数选择完整流或分声道。**
- **收听支持标准 PCM/WAV 音频及 Opus 两种格式，浏览器直接打开收听 URL 应显示原生音频播放控件，点击即可收听，无需专用客户端或自定义网页播放器。HTTP 成功响应必须使用与实际音频匹配的标准 `audio/*` Content-Type。**

用户已授权按阶段实施、RED/GREEN 测试、逐阶段提交推送、查询额度，并最终交付增量替换包。协议修订应先反映到 S0，再进入依赖它的实现阶段。

不包含：录音回放、节目编排、效果链、云控制台、账号平台、浏览器播放器、集群、自动部署以及完整接收端 GUI。不同流不自动混音；本地监听不从服务端绕回。

## 2. 术语与规划假设

| 名称 | 含义 |
| --- | --- |
| 广播节点 | 一种 JACK-only Node v4 类型，一个实例管理多条流及其输入、监听输出 |
| 流/轨道 | 一个独立发布和订阅的音频对象，包含 1/2/6/8 个同步声道 |
| 声道 | M、L、R、C、LFE、Ls、Rs、Lrb、Rrb 中的一项 |
| 全局连接 | 同一 WinJACKNexus 进程共享的服务器地址、发布凭据及连接状态 |
| 完整流路径 | 订阅某一条流的全部声道，不表示把所有流混在一起 |
| 分声道路径 | 订阅某一条流中的一个原始声道，不做 downmix |
| 本地监听 | 从本机输入处理链直接到 JACK 输出，不表示远端已收到或已播放 |

“服务端连接客户端需要 bearer token”按 C/S 发布鉴权理解：发送客户端主动连接服务端，服务端校验发布者的 Token；不设计服务端反向拨号到客户端。普通听众主动连接同一服务端，不携带凭据。

实施采用本计划的 M/监听语义建议：M 为该轨广播及监听共用静音；S 仅用于本地监听独奏；每流保留独立同布局监听输出。音频传输以用户最新要求为准：UDP 上行、HTTP 实时下行，不再采用 PCM over WebSocket 音频传输。采样编码、UDP 包格式及 HTTP 响应封装以 [Protocol-v1.md](Broadcast/Protocol-v1.md) 为冻结契约，阶段证据见 [Progress.md](Broadcast/Progress.md)。

## 4. 系统结构与目录

```text
外部音源 JACK 输出
    → 广播节点每流 JACK 输入
    → 公共音频处理核心：增益平滑、静音、计量
        ├─ 有界音频队列 → 发布工作线程 → 全局 UDP 音频会话
        │                                  → Rust 服务端
        │                                  → 按 GET 参数选流/声道 → HTTP 持续响应 → 播放工具
        └─ 每轨监听开关及本地 Solo 门控 → 同布局 JACK 监听输出

GUI → 控制状态快照；GUI ← 电平/连接状态快照
服务端故障、断线或慢听众均不阻塞 JACK 回调和本地监听。
```

拟新增源码和产物：

| 路径 | 职责 |
| --- | --- |
| `src/bc/` | 广播节点适配、全局发布会话、协议封包及 CMake 入口 |
| `src/common/include/WinJACKNexus/Common/Broadcast*.hpp`、`src/common/src/Broadcast*.cpp` | 流/分类状态与离线可运行的音频处理；按实际职责拆分，不预建空层 |
| `src/ui/include/WinJACKNexus/UI/BroadcastWindow.hpp`、`src/ui/src/BroadcastWindow.cpp` | 公共控件组成的独立窗口 |
| `bc/server/` | 独立 Cargo crate，Rust 服务端及其测试，能单独构建 |
| `bc/listen/` | 最小 CLI 接收及播放工具；复用协议定义，独立于 JACK |
| `Develop/Broadcast/` | 可提交的模块、协议、音频、GUI 调用点及跨进程测试 |
| `Docs/Broadcast/` | 协议 v1、运行说明、阶段记录及参考图 |
| `<运行目录>/nodes/bc/sender/` | 节点 DLL、该模块语言资源及必要描述符 |

源码 `/src/bc`、节点部署 `/nodes/bc` 和网络 `/bc` 是不同层次的路径。此次用户所述“广播相关节点放到 /bc 子路径”落实为 `nodes/bc`；网络入口也统一使用 `/bc` 前缀，以便理解和部署。

只新增一种 Broadcast Sender 节点类型。多个流在其 GUI 中添加，不为每种布局制造独立节点类型。多个实例通过模块内会话服务共享进程级控制连接和 UDP 音频会话，每实例仍有独立流和 JACK 客户端；最后一个实例释放后才关闭共享会话。GUI 关闭不停止推流，模块卸载必须先回收工作线程和窗口。

服务端无需读取 WinJACKNexus 工程文件，不链接项目公共 DLL。必要的协议字段以文档及跨语言夹具保持一致。

## 5. 音频输入、本地监听与控制语义

### 5.1 布局及端口

| 布局 | 输入数 | 监听输出数 | 固定采样顺序 |
| --- | ---: | ---: | --- |
| Mono | 1 | 1 | M |
| Stereo | 2 | 2 | L, R |
| 5.1 | 6 | 6 | L, R, C, LFE, Ls, Rs |
| 7.1 | 8 | 8 | L, R, C, LFE, Ls, Rs, Lrb, Rrb |

建议短端口名为 `s<稳定短ID>_in_L`、`s<稳定短ID>_monitor_L` 等，Mono 后缀为 M。流名称和分类更改不改变端口身份；短 ID 在节点内唯一并随配置保存，不用显示行号。JACK client name 使用既有宿主管理方式。

每条流始终保留匹配布局的监听输出，监听关闭时写零，不通过反复注册端口实现开关。不增加主监听混音总线，不把环绕声自动折叠为立体声。用户可将所需输出接入现有设备节点或调音台。

新增、删除、改变布局均在控制侧准备候选配置和资源，再在安全边界替换。失败保留原状态及其他流；JACK 回调中不注册端口、不分配内存。删除仅移除目标流的端口和订阅对象。改变布局保留流 ID，更新格式代次，明确提示受影响连接需要重新接线并保存工程。

### 5.2 建议处理链

```text
输入 → 统一增益（全声道同值、平滑） → M 静音 → 总体计量
                                            ├─ 对外广播
                                            └─ Listen && SoloEligible → 本地监听输出
```

- 音量建议范围 −∞ 至 +12 dB，默认 0 dB，复用已有 dB 旋钮交互；不增加每声道增益和声像控件。
- M：该轨广播和监听都静音，流保持在线并发送同时间轴静音数据，避免将 M 混同断流。
- Listen：每轨默认关闭；只控制该轨本地输出，不改变广播音频、远端订阅和其他流。
- S：建议仅本节点实例的本地监听独奏，允许多选。无 S 时所有 Listen=on 的轨可监听；有 S 时仅 Listen=on 且 S=on 的轨输出。S 不自动打开 Listen，不跨实例影响监听，不改变任何广播流。
- 停止全局推流：停止网络发布并通知听众离线；本地监听继续。断网行为相同。
- 新建、工程恢复和实例重建时 Listen 均为 off；S 同时重置为 off，GUI 明确显示。正常编辑和关闭/重开 GUI 不重置正在运行的监听。
- 上述 M/S 规则须在实施前确认，确认后写入 UI 行为契约和信号级测试。

监听为发送前的本地即时信号，不包含公网传播、服务端排队及听众缓冲延迟。GUI 不能将其标成“远端监听”。

### 5.3 一个总体电平表

每轨只有一根总体柱，不显示八根子声道表。建议采用全部声道中最大绝对样本峰值：`peak = max(channel, frame, abs(sample))`，显示为 `20*log10(peak)` dBFS。这样单个声道过载不会被声道平均稀释；它是总体峰值表，不标作 LUFS 或总响度。

位置在增益和 M 之后、Listen/S 之前；显示正在提交给广播队列的本地信号，不能证明远端已收到。使用公共 MeterBallistics 处理显示衰减、峰值保持；削波提示依据原始测量峰值而非平滑值。静音底限、显示范围与公共表一致，不新增独立固定配色。不会为满足表头而加入 limiter。

## 6. 全局连接、稳定路径及鉴权

### 6.1 三层配置

1. 应用级连接配置：全局服务器基址、发布者 ID、凭据引用；同一进程所有广播实例共享，修改时明确提示影响全局。
2. 项目内节点状态：分类、流稳定 ID、显示名、布局、增益、M 等；不包含 Token 明文。
3. 运行状态：Listen/S、连接状态、队列及计量快照；不作为自动开启监听的恢复依据。

发布者 ID 在初次配置时生成并保存在本机设置，形成服务器命名空间；流 ID 使用稳定 UUID。复制轨道或节点必须获得新的流身份；正常保存/加载保持原 ID。S0 核实宿主复制流程如何区分恢复和克隆；若没有适用钩子，不隐式更改 Node ABI，先报告最小必要变更。重复发布冲突时拒绝后来的发布，不抢占现有广播。

### 6.2 路径规则

建议全局基址为 `https://stream.example.com:9443/bc`，只配置一次。可靠控制接口在该基址下完成鉴权、注册及 UDP 端点协商，控制实现可使用 HTTPS/WSS；音频上行本身不用 WebSocket：

| 用途 | 路径 | 鉴权 |
| --- | --- | --- |
| 发布控制入口 | `/bc/publish`，协商 UDP 端点和会话 | Bearer Token |
| 音频发布入口 | 服务端协商返回的 UDP 主机、端口及会话 | 绑定已鉴权发布会话，不携带明文长期 Token |
| 完整流收听 | `GET /bc/listen?publisher=<publisherId>&stream=<streamId>&channel=all&format=opus` | 无需 Token |
| 分声道收听 | `GET /bc/listen?publisher=<publisherId>&stream=<streamId>&channel=L&format=wav` 等 | 无需 Token |

例如完整 7.1 使用 `channel=all`，左前及低频声道分别使用 `channel=L`、`channel=LFE`。立体声允许 L/R；5.1 不允许 Lrb；Mono 可使用 M。省略 channel 等价于 all；重复或非法参数明确拒绝，不回退到其他流。流 ID 和声道仍构成逻辑父/子资源；用户最新指定的 HTTP 查询参数作为正式收听入口，旧稿路径示例不再作为必需接口，不另加一套路径别名。

“全局路径”表示所有轨共享发布配置、控制入口和 UDP 会话；完整流请求只表示一条流的全部声道。没有隐含的“所有流总混音”入口。

分类和名称只用作展示元数据，不拼入权威路径。因此改名、分类移动、重名都不改变已分享的订阅地址。GUI 提供复制完整流及分声道地址入口，不要求用户手输 UUID。

拟定 CLI 使用方式（不是已存在命令）：

```powershell
bc-server --bind 0.0.0.0:9443 --udp-bind 0.0.0.0:9444 --publish-token-file C:\Secure\bc-publish.token --tls-cert C:\Secure\server.pem --tls-key C:\Secure\server-key.pem
bc-listen --url "https://stream.example.com:9443/bc/listen?publisher=<publisherId>&stream=<streamId>&channel=all"
bc-listen --url "https://stream.example.com:9443/bc/listen?publisher=<publisherId>&stream=<streamId>&channel=L"
```

浏览器或常见播放器直接使用同一个 URL，不先调用私有订阅 API：

```text
https://stream.example.com:9443/bc/listen?publisher=<publisherId>&stream=<streamId>&channel=all&format=opus
https://stream.example.com:9443/bc/listen?publisher=<publisherId>&stream=<streamId>&channel=L&format=wav
```

`format=wav` 返回 PCM/WAV；`format=opus` 返回 Ogg Opus。省略 format 建议默认 opus；未知格式返回明确错误，不返回与请求不符的内容。两种格式均覆盖单声道、立体声、5.1、7.1 和有效分声道选择。

### 6.3 Token 与公开收听

客户端在 `/bc/publish` 的可靠控制请求中发送 `Authorization: Bearer <token>`。服务端在建立发布会话和流注册前校验；无凭据或错误凭据拒绝。UDP 音频必须绑定该鉴权会话，不能仅凭可猜测的流 ID 或源地址获得发布权限；会话校验、抗伪造与重放规则在 S0 冻结。长期 Token 不逐包发送。听众的 HTTP GET 不需要 Bearer Token，也不能用于流注册。首版可采用服务端配置的静态发布 Token，不实现 OAuth 登录或签发平台。

发布 Token 不放在 URL、工程 JSON、UDP 明文包、日志或截图里。客户端 GUI 使用密码显示模式；本机持久化建议采用 Windows Credential Manager，项目和普通配置只存凭据引用。服务端从受权限保护的文件读取 Token，日志脱敏。公网控制及收听入口默认 HTTPS/WSS 并验证证书，不加入忽略证书校验开关；明文 HTTP/WS 仅用于显式配置的本机离线联调。TLS 不保护独立 UDP 音频包；UDP 会话的完整性及所需传输保护必须单独定义，不能宣称控制连接的 TLS 已覆盖媒体。

公开收听无需 Token，这是预期访问边界；知道地址的人可以收听。服务端不为听众暴露发布 Token 或私有本机配置。首版不增加公开全站流目录。

Token 使用原则参考 [RFC 6750](https://www.rfc-editor.org/info/rfc6750/)；本项目只采用 Bearer 请求头语义，不据此扩大为完整 OAuth 系统。

## 7. 传输、协议与 Rust 转发

### 7.1 技术取舍

| 方案 | 对目标的适配 | 首版决定建议 |
| --- | --- | --- |
| PCM/WAV + UDP 上行，HTTP 实时下行 | 标准未压缩音频路径；发送端产生 PCM，服务端按选择写 WAV 头及音频字节 | 按用户要求纳入首版 |
| Opus + UDP 上行，HTTP Ogg Opus 下行 | 节省带宽并采用标准浏览器音频容器；发送端编码完整流及分声道，服务端只封装转发 | 按用户要求纳入首版，建议为默认收听格式 |
| WebSocket 承载音频 | 有序可靠，但音频上行会受 TCP 队头阻塞影响 | 旧方案撤销，WSS 只可用于控制 |

UDP 是指定的音频上行传输，用户另行要求同时支持标准音频和 Opus；此处将标准音频落实为 PCM/WAV，不能只实现其中一种。UDP 不能降低相同 PCM 数据的固有带宽，也不提供自动拥塞控制；其主要收益是允许过期实时音频丢弃。HTTP 下行仍有可靠传输带来的等待，不能把整条链路描述成无队头阻塞。参考图 OPUS 128 kbps 不作为固定码率要求。

JACK 本地输入与监听保留实际时钟和浮点处理。网络 PCM 位深、WAV 声道掩码、Opus 采样率/帧长/码率，以及 JACK 时钟不匹配时发送端的重采样方式，在 S0 一并冻结；服务端不重采样。作为带宽参照，48 kHz/float32 裸音频 Mono 1.536、Stereo 3.072、5.1 9.216、7.1 12.288 Mbps；16-bit PCM 为其一半，均未含网络头。部署预算还要计入 Opus 完整流及分声道变体，不能把编码带宽只算一次。

听众必须通过普通 HTTP GET 请求获得持续实时音频响应，不先建立 WebSocket 或 UDP 会话，不需要 Token。HTTP 响应体承载可连续播放的音频，不能只返回订阅地址、文件下载链接或 JSON 状态。最小 CLI 必须通过该 HTTP 入口播放，输出设备无法承载布局时明确失败，不自动丢声道或 downmix。

### 浏览器与通用播放器收听契约

- 成功响应为 HTTP 200。WAV 使用 `Content-Type: audio/wav`；Ogg Opus 使用 `Content-Type: audio/ogg; codecs=opus`，响应体分别是真实 WAV 或 Ogg Opus，不能给裸 PCM/裸 Opus 随意贴 MIME 标签。
- 使用 `Content-Disposition: inline`（或省略该头）及禁止缓存的直播响应；不能设置 attachment 强制下载，不能返回 HTML、JSON、application/octet-stream 或私有 MIME 来替代音频。
- 浏览器直接导航到带参数的 URL，显示浏览器自带播放/暂停控件，用户点击可持续收听。无需自建网页、JavaScript 解码、插件、扩展或专用客户端。自动播放策略不作为失败：要求能点击播放，不要求绕过浏览器手势限制。
- 直播不要求已知总长度或下载完再播放；按 HTTP 版本采用正确流式响应，不伪造 Content-Length、不攒完整文件。WAV 未知长度的具体头格式及长期连续播放行为须实测，不能只验证短 WAV 文件。
- Opus 用标准 Ogg 封装，支持中途加入、新听众独立头信息及时间轴；不把 UDP 私有包头传给 HTTP 播放器。
- Opus 在发送端编码；完整多声道码流不能直接拆成可独立解码的单声道，因此发送端另产出所需单声道 Opus 变体，服务端按参数选择和封装，不解码/重编码。Mono 完整流与 M 可复用同一变体。
- PCM/WAV 的分声道选择只选原始 PCM 字节并输出正确 WAV 布局，不能为降低成本改成发送所有声道让浏览器自行选择。
- 兼容目标为原生浏览器播放、常见支持相应格式的 HTTP 音频播放器和本项目最小 CLI；不以专用 CLI 成功代替浏览器成功。S0 固定浏览器/播放器测试矩阵，S2/S5 实际验证控件、开始播放、时间推进、暂停后恢复直播及响应中断。
- 多声道码流必须保持真实布局；立体声设备上的浏览器播放成功只证明解码/播放，不能证明实际 7.1 硬件输出。通用播放器兼容性按实际版本和平台记录，不声称所有历史播放器都支持所有编码。

[RFC 7845](https://www.rfc-editor.org/info/rfc7845/)定义 Ogg Opus、声道映射及实时流时间轴。WebKit 官方 [Safari 18.4 更新说明](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)可用于核对 Ogg 音频支持版本；浏览器可用性仍以实际 live URL 验证为准。

### 7.2 协议 v1 草案

采用可靠控制连接加 UDP 音频上行，所有轨共享发布会话。控制可用 HTTPS/WSS 的 JSON 消息；若用 WSS，其规则参考 [RFC 6455](https://www.rfc-editor.org/info/rfc6455/)，但不得在该连接上传输连续音频。下行是 HTTP 流式响应。

控制消息至少包括 hello、register/update/unregister、ack/error、stream-online/offline/format-change。注册包括协议版本、publisherId、streamId、显示名、分类显示路径、layout、channelOrder、sampleRate、sampleFormat 和格式代次。

发送端按时钟形成短音频块，适配 JACK 回调块长，不假设回调正好等于网络包。完整 7.1/48 kHz/float32 的 10 ms 音频已达 15360 字节，不能直接放进单个 UDP 数据报。以总 UDP 应用数据报不超过 1200 字节作为初始预算，包含应用头和会话校验开销；按声道与连续样本片段拆包，避免依赖 IP 分片。S0 冻结实际帧长及安全载荷预算。

包头至少包括 magic、协议版本、消息类型、流句柄、会话代次、格式代次、递增数据报序号、首样本位置、块号、片段编号/总数、样本数、声道掩码及载荷长度。头字段采用固定约定字节序，PCM 显式为 little-endian；具体偏移及会话完整性字段在 S0 冻结并制作跨语言夹具。旧稿尚未冻结的 56 字节夹具不作为新 UDP 协议定稿。

载荷区分 PCM 与 Opus，包含编码和完整流/单声道变体身份。PCM 按冻结的样本格式、声道顺序及分包规则重组，服务端选择 PCM 声道并封装 WAV；Opus 选择发送端已编码的完整流或对应单声道变体，重组编码包并封装标准 Ogg。服务端不做混音、效果、解码、重采样或转码。封装及传输适配属于转发职责，不扩大为 DSP。PCM 缺片补静音、Opus 缺包时间轴及容器连续性分别定义，不把 PCM 补零规则套在压缩音频字节上。

服务端验证会话、包长、版本、布局/掩码、片段范围和已注册句柄，拒绝越界或格式不符；重排窗口内去重，过期包及旧会话包直接丢弃。格式更新时按已冻结 HTTP 封装能力处理；若不支持响应内变更，则结束旧响应，由客户端按同一 URL 重连获取新格式，不拼接不兼容音频。样本位置用于连续性；控制 RTT 不当成端到端音频延迟。

### 7.3 工作线程、容量与错误行为

- JACK 回调仅进行有界处理、写本地输出及写预分配队列；不访问网络、磁盘、GUI，不获取会等待的互斥锁。
- 每节点设置有界 SPSC 音频队列，工作线程汇入全局会话；队列满时回调丢弃当前待发块并记计数，不能等待听众。网络线程恢复后丢弃超过时限的旧块，以序号缺口告知接收方。
- 初始建议：发送积压最多 100 ms；听众待发数据最多 100 ms；接收抖动缓冲目标 40 ms、上限 100 ms。它们是初始配置值，S1/S2 用受控节流验证后冻结，不承诺公网固定延迟。
- 慢听众只影响自己的连接；超预算丢旧数据并发出间隙状态，持续阻塞超过 2 秒关闭该听众连接。其他听众和发布者不等待它。
- 音频缺口按时间轴插入静音，不循环播放旧音频；累计过期数据清理到当前直播位置，不无限追赶。
- UDP 必须覆盖丢包、乱序、重复、迟到、截断、分片缺失、MTU 边界和会话过期。首版不重传过期音频，不自动增加 FEC 或重传协议。工作线程按音频时钟节奏发包，避免把大批积压一次突发发送；持续超出预算应报告过载，而非无限提高发送量。
- UDP 绑定地址及端口由全局配置和可靠控制协商，不允许每轨另设服务器；明确防火墙与 NAT 的单向发布要求。未经验证的源端点不得触发向任意第三方的大流量转发。
- 普通网络失败建议 1/2/4/8/16/30 秒上限退避重连，停止推流可取消；401 不无限重试，显示凭据错误，修改后再连接。
- 未知路径/流返回 404，已知但离线返回 503，非法声道返回 400，发布身份占用返回 409；升级后的错误使用稳定机器码和明确关闭原因。
- 断开发布连接后立即标记该会话的流离线并通知听众；接收端显式重连订阅。清理时核对会话代次，防止旧会话释放误删新会话注册。

### 7.4 Rust 服务端依赖与部署

建议 Tokio 的 UDP socket 接收媒体，Axum 提供发布控制和带参数的 HTTP 音频流式响应；serde/serde_json 管理控制消息，bytes 表示共享载荷，维护中的 TLS 库提供 HTTPS/WSS。实现时核对 Rust 工具链与依赖兼容版本并提交 Cargo.lock，不在计划中伪造已解析依赖。

[Axum 官方文档](https://docs.rs/axum/latest/axum/extract/ws/index.html)提供 WS 升级和读写拆分入口。[Tokio broadcast 官方文档](https://docs.rs/tokio/latest/tokio/sync/broadcast/index.html)说明有界扇出和慢接收方行为；这可用作设计依据，但仅有队列容量并不能限制已写入 socket 的积压，仍需写超时及每连接预算。

首版提供独立可执行文件、配置示例和控制台日志；不自动安装系统服务。生产启动依赖仅为该服务端程序、配置、Token 文件和 TLS 证书，不依赖 WinJACKNexus 进程。Rust 构建产物使用既有 `build` 下的指定 target-dir，不生成根目录 `target` 或其他构建树。

## 8. GUI 与配置管理

参考图见 [广播发送节点布局参考](Broadcast/广播发送节点布局参考.png)。图片中的双柱电平、立体声标记、码率数字及地址只为示意，不直接复制为行为契约。

- 顶部：共享服务器地址、连接/鉴权状态、全局推流操作；凭据通过共享内容控件进入设置。修改全局地址时显示影响所有广播实例的说明。
- 左侧：多级分类树及新增分类、新增流、重命名、删除、移动入口。根级允许直接放流。分类和名称按纯文本呈现。
- 右侧顶部：当前选择、布局及可复制的完整流/分声道地址。
- 主区域：按当前分类筛选轨道卡片；选分类包含其后代，选流定位相应轨道。每轨名称、分类、布局、单柱表、M、S、音量旋钮、默认关闭的 Listen 开关。
- 底部：推流状态、实际上传码率、发送丢块、服务端观测的 UDP 序号缺口/迟到/重排计数、连接时长及必要诊断入口；区分发送端队列丢块与接收侧缺包，注明统计窗口及计量位置，不将单次乱序立即算作最终丢包。
- 使用共享 SplitField/ScrollField 处理左右尺寸和横向轨道滚动；长名称省略并提示全文，缩放时不得压住控制。
- GUI 语言绑定遵循现有 i18n API；切换语言或主题不修改用户名称、流身份、监听开关或音频状态。
- 复用 ConsoleKnob、FxLevelMeterWidget 单柱竖向模式、ActionButton/ToggleField、GroupPanel 和现有主题。M/S 不另画私有按钮；普通菜单使用 Qt 原生样式。
- 窗口只保留遵循应用 30/60/120 FPS 的刷新调度；隐藏时停止 GUI 采样刷新，不停止音频和网络。复用电平控件时核对其计时器，避免窗口和子控件重复刷新。

分类以 categoryId、parentId 表达树，流保存 categoryId。禁止把分类移动到自己或后代；同级重名可允许，因为身份由 ID 决定。删除非空分类先给出“移动内容到父级/连同流删除”的明确操作，不静默删除广播流。

流配置保存 schemaVersion、streamId、portId、displayName、categoryId、layout、gainDb、mute；类别保存 categoryId、parentId、name、order。恢复校验先构造候选状态，成功再应用，避免半恢复状态。Listen 和 Solo 的 off 恢复规则不被保存状态覆盖。服务器地址与凭据引用存全局设置，不从任意工程加载时覆盖全局服务器。

## 10. 验证与构建执行规则

### 10.1 必须覆盖的证据

- 四种布局使用不同声道特征信号；接收完整流和各子路径后核对声道身份，不能只验证“有非零数据”。
- 证明 M 不断开流、Listen/S 不修改广播数据、增益仅应用一次、任一声道过载都会触发表头提示。
- 从新建及工程恢复验证监听默认关闭；重开窗口不得误关闭当前监听。
- 服务端鉴权测试包括未升级前拒绝和听众连接不能发布；公开收听成功不能被当作漏洞。
- 通过真实进程和 socket 完成转发测试，不用内存 mock 冒充网络链路；不需要 JACK 服务。
- 通过真实 UDP 上行及真实 HTTP GET 响应完成收听链路；参数覆盖完整流、每个声道、默认 all、缺失/重复/非法参数及不存在/离线流。验证 Content-Type 与实际响应内容匹配，并确实可实时连续播放。
- WAV/Opus 两种格式分别测正确 audio/* 响应头、标准容器解码、浏览器原生播放控件及实际时间推进；不以裸字节下载或 CLI 私有解码替代通用收听。PCM 用确定量化后的样本比对；有损 Opus 用独立声道特征、可接受误差及时间轴证据，不要求有损编码逐样本等值。
- 对 UDP 注入可复现的丢包、乱序、重复和迟到，覆盖 1200 字节预算、完整 7.1 分包重组和会话防伪造；证明其他流及 HTTP 听众不被慢接收方拖住。HTTP 断连必须及时回收订阅资源。
- 离线节点回调测试能够证明输入到本地输出缓冲的行为；真实 JACK 端口连线、设备播放和音频不断流需单独记录，不把离线测试写成现场端到端 PASS。

## 12. 实施前集中确认的决定

1. **M/S 语义**：建议 M 同时影响广播和本地监听；S 只对本节点本地监听独奏，始终受 Listen 开关约束。若用户需要广播 Solo，应明确授权它对其他远端订阅的影响。
2. **监听输出形式**：建议每流提供与输入相同布局的独立 JACK 输出，多个 Listen 开关可同时打开，不增加监听混音或自动 downmix。需要单一监听总线时属于不同路由方案，须先决定布局及混音规则。
3. **传输及播放格式（用户已指定）**：音频发布走 UDP；听众通过 HTTP GET + 参数获取实时音频，无需 Token；标准 PCM/WAV 与 Ogg Opus 两种格式均支持。成功响应必须是对应标准 audio/* 类型和真实音频内容，浏览器直接开 URL 显示原生播放控件并可点击收听。服务端不转码，编码及必要重采样由发送端完成。S0 冻结具体参数及测试矩阵，UDP 不替代编码压缩。
4. **全局与路径解释**：建议同进程所有广播节点共享一组服务器配置和一个发布会话；`/bc` 同时作为节点部署子目录和网络统一前缀，分类不进入稳定订阅地址。此解释应在协议冻结前确认。
