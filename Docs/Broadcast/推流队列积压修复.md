# 推流队列积压修复

日期：2026-11-07。

现场截图显示源丢帧2048、过期帧288，发送端报 `Audio source exceeded publishing queue budget; restart publishing`。发送端停止会移除服务端发布会话，因而收听链接出现 `stream_unavailable`。本次处理发送线程的积压消费问题，不改收听协议或服务器错误码。

## 根因与改动

旧 Worker 每次定时器唤醒每流只读取10ms音频。定时器并不保证每1ms准时执行；当唤醒间隔持续超过10ms时，消费速率落后，队列填满并出现过期/不连续帧。用生产Worker、48kHz/256帧独立生产线程和20ms发送唤醒的离线网络测试复现：旧代码丢43520帧、过期43200帧，测试失败。该回归模拟调度延迟，不声称测得现场实际唤醒间隔。

修复后每次唤醒以10ms为一批，每流最多处理10批，读空即停止。保持现有100ms队列和时效预算，保留generation隔离、连续性校验及超预算停止策略，不扩大缓冲、不无限追赶。没有改变JACK音频回调或音频线程行为，也不引入新的实时线程工作。
